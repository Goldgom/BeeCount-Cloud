# 资产与流水数据获取

## 推荐顺序

1. 平台官方只读 API：用于自动余额、权益、持仓和历史事件读取。
2. 平台官方 CSV/XLSX 账单：用于补历史、覆盖检查及对账。
3. 受控 CLI 输出导入：适合已有采集工具，不允许在网页配置任意 shell 命令。
4. 安卓通知：用于日常消费及时发现；通知可能关闭、合并、隐藏金额或被系统限制，不能保证完整。
5. 截图/OCR：仅在没有结构化数据时补录，需要确认金额、币种、日期与估值类型。

## 币安应读取的维度

| 模块 | 关键字段 | 对账要求 |
| --- | --- | --- |
| 现货 | 各币种 free / locked | 锁定不等于支出；零余额需成功读后确认 |
| 资金账户 | 可用、冻结及锁定余额 | 与现货分开，内部划转不当收入 |
| Simple Earn | 活期与定期产品、持有金额、独立收益 | 不能只查现货就称全部币安资产 |
| PM / 合约 | 钱包余额、净权益、保证金、可用、浮盈亏、负债 | 净权益覆盖式计入，不再叠加名义持仓价值 |
| 成交 | 交易 ID、symbol、方向、数量、成交价、手续费币种 | 分页和游标；现货 myTrades 必须指定 symbol |
| 资金记录 | 充值、提现、内部划转、资金费、利息、申赎、收益 | 区分外部流入流出与内部转账；按外部 ID 去重 |

官方现货文档：
- https://github.com/binance/binance-spot-api-docs/blob/master/rest-api.md
- https://developers.binance.com/docs/binance-spot-api-docs/rest-api/account-endpoints

`GET /api/v3/account` 返回现货余额，不代表理财或 PM 已覆盖。
`GET /api/v3/myTrades` 必须提供 symbol；当前文档限制 limit 最大 1000，startTime 与 endTime 间隔不超过 24 小时。实现须按对应模块文档检查其独立限制，不能推定所有接口相同。

## 安全边界

- 只启用读取权限，不开交易、提现或划转权限；推荐平台 IP 白名单。
- 凭据只能通过应用安全表单提交，服务端加密存储；列表、错误、日志、导出均不返回可用凭据。
- CLI 使用预定义格式导入或服务器管理员固定的受控适配器，不接受用户提交可执行 shell 字符串。
- 所有平台访问必须隔离租户；同步超时不重放账务变动；读取失败不清零。
- 配置连接不代表采集成功；应分别显示连接、授权、采集和估值状态。

## 正确性与自动更新

- 每一组件保留原币十进制数、采集时间、平台更新时间（若有）、来源、估值时间与覆盖状态。
- 绑定既有账户必须明确覆盖，不把同步值和手动余额相加。
- 模块失败为未知或陈旧，确认成功的空结果才是零；保留上次成功值和失败原因。
- 轮询称为近实时并显示间隔，不宣称逐笔实时。逐笔实时需要支持的官方事件流，以及断线补拉与定期全量校验。
- 非稳定币需要行情估值；USDT 不隐式等于 USD，外汇缺失不得混入人民币合计。
- 当前值只解决“有多少”；解释“去了哪里”需要完整资金记录；计算收益还需要期初/期末估值、外部现金流和费用。数据不齐时收益返回未知。

## 日常消费

安卓开启通知使用权后，本地采集待确认；支付成功与转账、退款、余额提醒分别识别。每周或每月导入微信/支付宝/银行官方账单，检查漏单和重复。采集覆盖率通过账单核对证明，而不是由通知服务处于运行状态推定。
